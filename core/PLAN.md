# План ядра МТС Energytool

Рабочая ветка: `core`, основа — актуальный командный `main` от 12 ноября 2026.
Команда: владелец делает ядро и интеграцию; остальные участники — backend, frontend и база знаний. Старое распределение пяти ролей в ранних документах не используется.

## Задачи и приёмка

| ID | Задача | Зависимости | Проверка готовности |
|---|---|---|---|
| C1 | Контракт backend и конфигурация | — | Фабрика create_core, общий CoreRequest/CoreResponse, ключи только в окружении |
| C2 | Документы и смысловые фрагменты | C1 | TXT/MD/CSV/JSON/DOCX/PDF, устойчивые ID, таблицы, безопасный ZIP, ошибки пустых/неподдерживаемых материалов |
| C3 | BM25 и контекст по истории | C2 | Одинаковая нормализация, детерминированная выдача, источник и актуальная реплика |
| C4 | Qwen-совместимый клиент и инструкция | C1 | URL без самовольного /v1, таймауты, ограниченные повторы, отсутствие смены провайдера |
| C5 | Ответ и проверка оснований | C3,C4 | Существующие ID и точные цитаты; некорректный JSON/ссылка не превращаются в ответ |
| C6 | Явный demo-режим | C2,C5 | Работает без реального API и данных, всегда помечен как вымышленный |
| C7 | Общий solution.py | C5 | Независимые ID, история внутри строки, CSV UTF-8, все ID, общий дедлайн и сохранение результатов |
| C8 | Плоский ZIP и валидатор | C7 | Только корневые .py и requirements.txt; чистый запуск без backend и БД |
| C9 | Тесты и отчёт | C1–C8 | Парсинг, поиск, HTTP-сбои, история, изоляция, CSV, проверка ZIP и интеграция с backend |

Сначала реализуется BM25 baseline. Эмбеддинги, гибрид и реранкер — отдельные измеряемые улучшения после получения данных, схем API и dev-набора; неподтверждённые endpoints не добавляются.

## Подтверждённые ограничения входов

Владелец сообщил, что настоящая база, demo-файлы, пример сабмита и доступ API пока отсутствуют. Их содержимое не выдумываем. Официальный разрешённый requirements.txt и версия Python платформы не проверены. Ветка реализует и проверяет код на синтетических материалах; оценка платформы и работа реального Qwen этим не подтверждаются.

Согласно DECISIONS.md ядро не управляет аккаунтами, согласиями и записью заявки. Резюме — только черновик; прав и идентификаторов аккаунта ядро не получает. Состояние диалога не хранится между вызовами.
