# Копия и восстановление SQLite

Команды выполняются из корня проекта в Python-окружении backend. Они не вызывают
ядро или модель. Копия содержит аккаунты, сессии, диалоги и контакты заявок:
это закрытые данные. Каталог backups/ исключён из Git и Docker-контекста.

## Создать и проверить

```bash
mkdir -p backups
DATABASE_URL=sqlite:///./energytool.db python -m backend.backup create --output backups/snapshot.db
python -m backend.backup verify --source backups/snapshot.db
```

Работающий backend можно не останавливать: используется SQLite Backup API,
а не копирование основного файла без WAL. Результат — согласованный снимок на
момент копирования; последующие записи в него не попадают. Новый файл создаётся
с правами 0600. Существующий путь, включая ссылку, не перезаписывается.
Команда проверяет целостность, внешние ключи, обязательные поля и текущую ревизию
Alembic. JSON содержит только статус, ревизию и количества строк по таблицам.
Код выхода 0 — успех; 2 — отказ. При ошибке собственный незавершённый файл удаляется.

## Проверить восстановление в отдельный файл

```bash
python -m backend.backup restore --source backups/snapshot.db --output backups/restored.db
python -m backend.backup verify --source backups/restored.db
```

Команда никогда не заменяет рабочую БД. Для переключения остановите backend,
сохраните прежнюю БД и задайте DATABASE_URL на восстановленный файл. Запустите
один процесс и проверьте вход, историю и заявку. Если требуется откат, остановите
его и верните прежний URL. Не запускайте две реплики на одной БД.

Копия восстанавливает и прежние серверные сессии. Используйте закрытое окружение
для пробного запуска. Проверка схемы рассчитана на текущую версию приложения:
для старой копии сначала используйте соответствующий релиз, затем штатные миграции.

## Docker

```bash
docker compose exec backend python -m backend.backup create --output /data/snapshot.db
mkdir -p backups
docker compose cp backend:/data/snapshot.db backups/snapshot.db
```

Имя снимка должно быть новым. Копия внутри того же тома не защищает от удаления
тома: перенесите её в отдельное закрытое хранилище. Восстановление в контейнере
также допускается только в новый путь; для переключения задайте новый DATABASE_URL.
Не используйте `down -v` для обычного перезапуска.

## PostgreSQL

Модуль намеренно не пытается копировать PostgreSQL как файл. Для него используются
штатные `pg_dump`/`pg_restore` и отдельная проверочная база; реквизиты передаются
через защищённое окружение или pgpass. Эти команды не реализуют перенос данных
SQLite → PostgreSQL. Приложение и Alembic по-прежнему выбирают СУБД через DATABASE_URL.

## Проверка реализации

`python -m pytest tests/test_backup.py -q`: восстановление входа, истории и
созданной заявки, работа с WAL, режим файла, отказ при существующем назначении,
повреждённом источнике, неверной схеме и нарушенных связях. Данные вымышленные;
рабочая БД пользователя не используется.
