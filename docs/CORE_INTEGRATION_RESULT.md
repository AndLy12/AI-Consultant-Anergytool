## Изменения на стороне backend

- Фабрика Данька сразу предоставляет синхронный respond, поэтому используется
  напрямую. Прежний async-адаптер остаётся для совместимости старого протокола.
- Backend и check_core закрывают ресурс ядра через необязательный close().
- /health и интерфейс показывают core_demo отдельно от CORE_MODE: real не
  означает реальную модель, если одновременно включён CORE_DEMO=true.
- Для тестового интерфейса используется demo-база «Учебный стенд Альфа».
  Источники, предупреждения и ответ сохраняются в истории аккаунта.
- Настройки ядра передаются через Compose; compose.knowledge.yaml подключает
  настоящую базу read-only в /knowledge, отдельно от SQLite в /data.
- Docker устанавливает RAG-зависимости из согласованного web-lock.
- Локально создана .venv-core на Python 3.12. Прежняя .venv на 3.14 сохранена.
- Общий CI запускает pytest, чтобы проверять и новые tests/core. Платформенные
  зависимости проверяются отдельно от веб-lock. Python 3.10 не поддерживается
  новой конфигурацией: ядро использует asyncio.timeout и согласованный Python 3.12.
- Старые проверки baseline адаптированы к новому CLI и QwenClient, без скрытых
  пропусков и без изменения кода ядра ради старых ожиданий.

## Что ещё не подтверждено

Настоящий Qwen не вызывался: адрес, ключ и модель локально отсутствуют. Demo
проверяет настоящее ядро с тестовым клиентом, а не качество генеративной модели.
Docker Engine на Mac отсутствует; два режима Docker проверяются в CI ветки.
Итоговые статусы CI проверять для текущего коммита.

Для реального запуска нужны LLM_BASE_URL/LLM_API_KEY/LLM_MODEL (или аналоги),
CORE_MODE=real, CORE_DEMO=false и путь к закрытой базе. Ключ не передавать в чат.
Затем проверяются вопросы с источниками и время на настоящем API. После этого
можно оценивать качество, а не только техническую интеграцию.
