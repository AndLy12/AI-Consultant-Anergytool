# Архитектурные решения

Согласовано с владельцем 12 ноября 2026.

1. Две поставки: платформенный ZIP и веб-прототип с Docker и документацией.
2. Единый Python-backend; общее ядро для веба и solution.py, без отдельного сервиса ядра.
3. SQLite, SQLAlchemy, Alembic; PostgreSQL через DATABASE_URL. Перенос накопленных
   данных является отдельной операцией; схема и сценарии проверяются на двух БД.
4. Email/пароль, история в аккаунте с разных устройств. При внедрении — авторизация
   МТС с сохранением внутренних ID пользователей.
5. По решению владельца без писем подтверждения и восстановления пароля.
   Email является логином, принадлежность адреса не проверяется.
6. Серверные сессии с HttpOnly-cookie и хешами токенов, CSRF для изменений.
   Выход завершает сессию текущего устройства.
7. Новый диалог закрывает прежний активный диалог аккаунта. Архив доступен
   для просмотра, в новый контекст не включается. Есть явная кнопка закрытия.
   Закрытие вкладки не является надёжным сигналом серверу.
8. Карточка заявки и явное согласие перед созданием. Проверка версии карточки,
   одна заявка на диалог, повтор возвращает тот же ID. После заявки можно общаться.
9. Модель готовит ответ и черновик резюме; backend контролирует права и запись.
10. Свой OpenAI-совместимый Qwen API в разработке, API организаторов при проверке.
    Ключ, URL и модель через окружение; автоматической смены провайдера при сбое нет.
11. Один процесс backend. При старте прерванные processing-сообщения становятся
    failed. Несколько реплик потребуют другого восстановления и общего rate limiter.

Авторизация МТС, почта, CRM и публичный хостинг не подключены.

## Улучшение консультаций 14 ноября 2026

После успешного скоринга v3 с результатом 0.0798 владелец запросил повышение
качества ответов. Ядро принимает связный ответ модели вместе с проверяемыми
цитатами. Старый формат выбора цитат сохраняется для существующих клиентов.
Проверка цитат подтверждает их происхождение, но не все утверждения пересказа.
Одна коррекция структуры или оснований разделяет исходный дедлайн и лимит
параллельности. Рост конкурсной оценки этой версии пока не измерен.

## Проверка перед отправкой

Данёк сравнивает готовые CSV в двух порядках с эталонами demo с помощью scripts/judge_answers.py. Модель генерации получает только вопрос, историю и контекст базы. Решение о выборе версии учитывает ошибки по строкам, время и разбор ответов. Локальный baseline и модель судьи фиксируются в отчёте.


Для консультации используется повторная проверка по тем же документам. Внутренняя
схема проверки содержит замечания, отдельный следующий вопрос и итоговый объект.
Публичные поля CoreResponse сохранены. При технической ошибке проверки возвращается
первоначальный структурно валидный ответ с предупреждением. Это не гарантирует
устранения всех смысловых ошибок.

Настройки совместимости API согласуются по отказам провайдера. Приоритет форматов
json_schema, затем json_object, затем обычный текст с проверкой JSON приложением.
Ошибки авторизации, таймауты, лимиты и неверные ответы модели учитываются раздельно.

Переданный архив ROLE3_PRIVATE и отчёт Ани используются как локальные сценарии проверки.
Их внутренние критерии не объявляются официальной разметкой организаторов. После
первого запуска отложенного набора и исправления найденной ошибки этот набор
считается разработческим. До отдельного решения владельца кандидат на сайт не отправляется.


Релиз для передачи называется 6v. Ошибка превышения контекста выделена в категорию
context_length и не меняет настройки совместимости API. Проверка повторного ответа
использует исходный бюджет; её незавершённость видна отдельно в review_incomplete.

Для известной ошибки переноса бесплатности расчёта на физическое обследование
добавлена узкая проверка формулировок по цитируемым источникам. Она снимает
неподтверждённое прилагательное, не объявляет работу платной и не назначает цену.
Запрошенные пользователем выдержки для черновика ею не переписываются.
