## Независимые от коллег задачи сопровождения

- `backend.backup`: согласованный снимок SQLite с WAL, проверка схемы/связей,
  восстановление в новый файл без перезаписи рабочего. Семь автоматических проверок.
- `/ready`: БД, ревизия Alembic и загруженное ядро; 503 при неготовности,
  без вызова внешней модели. Docker healthcheck использует этот маршрут. Пять проверок.
- `backend.manage`: отзыв staff для открытых сессий и очистка только истёкших
  входов, без удаления истории. Три автоматические проверки.
- `docs/API_CONTRACT.md` заменён актуальным v1; резервирование описано в
  `docs/BACKUP_AND_RESTORE.md`. Личные учебные файлы остаются вне коммитов.
- Аварийное восстановление проверяется не только TestClient: тест завершает
  собственный backend-процесс во время обращения к провайдеру, запускает новый
  и проверяет failed, отсутствие автоповтора и успешную следующую отправку.

Технические пункты 1–6 роли 1 реализованы. Пункт 7 (интеграционная приёмка)
имеет проверенное серверное основание; окончательное закрытие требует принятого
UI и настоящих ответов ядра. Внешний хостинг/HTTPS и авторизация МТС не входят
в подтверждённый текущий запуск. Перенос накопленных SQLite-данных в PostgreSQL
остаётся отдельной операцией, а не следствием смены DATABASE_URL.
