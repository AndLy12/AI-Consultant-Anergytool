## Готовность реального прогона

В закрытой папке подготовлены 12 критических сценариев с тремя повторами,
30 основных, 18 официальных, восемь независимых и семь шагов двух живых
цепочек. Всего 99 записей очереди с учётом повторов и пересечений, а не
99 независимых вопросов. Независимый набор не запускался на модели или
поиске и не использовался для настройки. Его SHA-256:
`893cf9779a7a758558ddf972de9c0ad4fa732b1fb0429b45348d849791c1cdd0`.

Предварительная проверка доступности
`role3-20261114-135744-6af65f65` создала паспорт, журнал и таблицу ручной
оценки. **99 записей blocked, ноль начатых и завершённых вызовов модели,
ноль оценённых консультаций.** Причина — отсутствие конфигурации отдельного
реального API. Это не 99 неудачных ответов и не выполненный содержательный
прогон. Параметры по умолчанию в паспорте обозначены как плановые, а не
наблюдавшиеся настройки платформы.

Реальный запуск инструмента для текущего кода Git, из корня проекта после
настройки окружения и установки зависимостей ядра:

```bash
python scripts/role3_acceptance.py --execute --suite smoke \
  --source-revision <полный-SHA> --criteria-status user_confirmed_preliminary
python scripts/role3_acceptance.py --execute --suite all \
  --source-revision <полный-SHA> --criteria-status user_confirmed_preliminary
```

Инструмент не импортирует отдельно переданный плоский v5. До согласования
его кода с Даньком нельзя выдавать такой прогон за проверку v5.
Без `--execute` формируется только очередь. Demo блокируется; при отсутствии
доступа ответы не выдумываются. После технической ошибки остальные попытки
блокируются до устранения причины. Для включения C12 нужен отдельно
согласованный `--include-context-fixtures`; строка меняется только в копии
контекста запроса. Подробные результаты сохраняются после каждой попытки,
ключ удаляется из сохраняемых значений, ошибки ограничиваются по длине.

В `runs/<run-id>/` остаются `passport.json`, `results.jsonl`,
`assessments.csv`, `summary.json`. Наблюдается структурированный результат
клиента, если вызов выполнен; скрытые рассуждения и заголовки авторизации
не запрашиваются. Оценки в CSV заполняет проверяющий. До этого успешность
консультаций автоматически не рассчитывается.

## Предварительные критерии и решение

Аня подтвердила: минимум 27 полностью успешных из 30 основных сценариев,
ноль критических дефектов, полное подтверждение критических фактов и
ограничений. Это внутренние предварительные критерии; итог релиза — за
владельцем. Неоценённые и заблокированные строки остаются видимыми.

**Решение для проверенного кода Git: генерация не проверена из-за
блокировки. Для v5 есть положительная платформенная оценка по скриншоту,
но ручная содержательная приёмка и соответствие Git не подтверждены.**

Пять сопоставлений веб/CSV, реальные повторы, живые диалоги и закрытие
дефектов после исправлений пока не выполнены. Блокеры и адресаты вопросов
перечислены в [отчёте для команды](ROLE3_TEAM_REPORT_2026-11-14.md).
