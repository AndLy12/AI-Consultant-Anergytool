# Объединение backend и командного репозитория

12 ноября 2026, по указанию владельца проекта.

- Основа общей истории: main, исходный коммит 308f571. Локальная разработка
  backend объединена обычным merge; force push не нужен.
- core/ сохранён без изменений относительно командного main. Это зона Данька.
- Backend-заглушка заменена аккаунтами, серверными сессиями, SQLAlchemy,
  миграциями, историей, staff-доступом и подтверждением заявок.
- Старые backend/storage.py и backend/web/* удалены из текущей версии,
  восстанавливаются из прежних коммитов. Прежняя демонстрационная SQLite из var/
  автоматически не импортируется в новую схему аккаунтов.
- backend.main:create_app перенаправляет в backend.app:create_app.
  run.py применяет миграции. requirements-backend.txt ссылается на веб-зависимости.
- Async answer(history) поддерживается адаптером, без переделки core/contracts.py.
  Требуется синхронная фабрика create_core(), возвращающая объект ядра.
  Для async HTTP-клиента сохраняется один event loop до остановки приложения.
- Даша использует docs/BACKEND.md и /openapi.json. Историческое API v0.1
  заменено. Аня использует инструкции запуска из README/docs/BACKEND.md.

Проверки: 29 тестов успешно выполнены на SQLite и PostgreSQL 18, включая
контракт async-ядра и HTTP-обмен с ним. Проверены pip check и JS-синтаксис.
Настоящий RAG/Qwen пока не подключён: в опубликованном core есть контракт
и заглушка. Новые непереданные файлы Данька не проверялись.
Docker Engine на этом ПК отсутствует, сборка образа остаётся открытой проверкой.

Диагностика публикации: сохранённая HTTPS-авторизация отвечает 403 на git push,
хотя API подтверждает права владельца. Это не доказательство достаточных прав
самого токена на запись Contents/Workflows. Существующая SSH-авторизация тем же
AndLy12 работает; dry-run подтверждён. Токен и приватный SSH-ключ не выводились.
Для push используется SSH, для fetch может остаться HTTPS.
