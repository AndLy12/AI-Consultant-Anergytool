# Продолжение ядра владельцем проекта

Дата: 15 ноября 2026. По прямому поручению владельца проекта работа над ядром временно продолжена после исчерпания лимитов Данька. Ветка: `codex/core-v7-continuation`, отдельный worktree. Исходная ветка Данька не переписывается.

## Фактическая точка передачи

Подтянута `origin/codex/core-intent-rag` на `a1e2d74`. Это новее `6ace0a0`, указанного в `CONTINUE_QA.md` для последнего длинного прогона. Исторические результаты на 82 ответа не являются проверкой последующих изменений.

После той точки Данёк согласовал схему результатов review с генерацией; уточнил исключение продукта и вопрос о свойстве; сохранил полезный ответ при проверке без замечаний; улучшил возврат к первой теме, коррекции клиента и региональные ограничения; обновил инструкцию V7. На полученном коде локально: 285 тестов проходят.

## Исправление продолжения

`QwenClient.review` теперь проверяет полный объект через существующий `AnswerReview`, даже если провайдер игнорирует JSON Schema или клиент перешёл в json_object. До изменения принимались отсутствующие поля отчёта, неправильный тип issues и посторонние поля. Неполный отчёт с вложенным insufficient_data мог затереть валидную консультацию.

Ошибка структуры преобразуется в безопасный ModelResponseError без значений Pydantic. Существующая обработка необязательной проверки сохраняет исходный ответ и источники, добавляя предупреждение. Проверка существования источников остаётся в assemble; проверка схемы не гарантирует смысловую достоверность ответа.

Пять новых тестов формата до исправления падали. Добавлен сквозной тест с имитацией HTTP: валидная генерация → неполный review → исходный answered с источниками и предупреждением. Полный pytest после исправления: **291 passed**, одно предупреждение Starlette. Это проверки без реальной модели.

## Доступ к модели и следующие действия

Удалённый API модели energytool-eval проверен с Mac. Первый запрос с базой выполнен за 13,2 с с двумя источниками без предупреждений.

В диалоге на a7a1793 модель приняла мощность склада за мощность проектируемой станции. Для фразы «Что нужно для оценки?» поиск пропускал список исходных данных. После исправления распознавания на том же запросе модель использовала раздел «Для солнечной станции», перечислила параметры и отделила целевую мощность станции. Осталась неточность: модель назвала сообщённую мощность присоединённой, хотя клиент этого не уточнял.

Во второй реплике исходного диалога видимый ответ верно учёл поправку и исключение солнечной станции, но в отдельном summary_draft сохранилось прежнее намерение. В следующем изменении исправлена сборка карточки. Полный набор автотестов после изменения: 292 прошли. Сравнение на полном разработческом наборе ожидает результатов предыдущего прогона Данька.

Исправлен черновик после исключения продукта. На сохранённом диалоге с прежним ответом Данька карточка содержит две строки: «мощность склада 900 кВт» и «нужен только учёт электроэнергии». Проверены пустой, устаревший и неполный черновики модели. Все 295 тестов прошли. Повторный живой прогон пока заблокирован: внешний API вернул HTTP 502.

Проверены три дополнительных случая сборки карточки. Явная поправка мощности второго именованного объекта заменяет прежнее значение этого объекта. После возврата к продукту карточка убирает прежнюю отдельную фразу «… исключаем». Когда клиент сообщает задачу и отдельным предложением просит резюме, карточка сохраняет задачу. Для неоднозначных ссылок на несколько объектов сохраняется хронология. Три новых регрессии падали до исправления. После исправления проходят 298 тестов, одно прежнее предупреждение Starlette. Удалённый API при проверке списка моделей вернул HTTP 502.
