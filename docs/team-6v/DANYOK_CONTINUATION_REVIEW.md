## Отдельная проблема утилиты QA

На предыдущем снимке `9e7d2b1` обычный `python -m pytest -q` на Windows дал 310 passed / 1 failed: `test_packet_audit_preserves_ids_and_does_not_claim_semantic_acceptance`. Та же ошибка воспроизводится на прежней ветке `codex/core-qa-cycle` (`f9cdd09`); с `-X utf8` все 311 тестов того снимка проходят.

Причина: в `scripts/role3_quality_eval.py` исходный raw JSON читается через `raw_file.read_text()` без явной кодировки, а JSONL читается как UTF-8. В окружении Windows с иной системной кодировкой русский текст расходится и проверка целостности отклоняет правильный пакет. Коллеге три: явно задавать UTF-8 при чтении JSON-пакета и проверить утилиту в окружении без UTF-8 по умолчанию. Его файлы в этой перепроверке не редактировались. До исправления запускать QA с `python -X utf8`.
