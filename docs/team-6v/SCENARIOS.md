# Сценарии проверки качества

Этот список — открытые синтетические примеры и рабочие критерии команды.
Он не содержит скрытой выборки сайта и не является официальной разметкой.
Наличие строки здесь не означает, что сценарий уже пройден: результат требует
версии кода, фактического ответа, источников и отметки проверившего.

## Намерение и выбор продукта

| ID | Что пишет клиент | Что проверяем |
|---|---|---|
| I01 | Панели не нужны, нужен учёт. С чего начать? | Нет обязательных источников про солнечные панели; есть данные для учёта |
| I02 | Учёт не нужен, нужны солнечные панели. С чего начать? | Обратный выбор: солнечная станция, без навязанной платформы учёта |
| I03 | Не солнечные панели, а учёт по арендаторам | Понимание конструкции «не X, а Y» |
| I04 | Отказываемся от солнечной станции | Отказанный продукт не становится обязательным |
| I05 | Не отказываемся от солнечной станции. Какие ограничения? | Двойное отрицание не исключает продукт |
| I06 | Нужно менять SIM? / SIM менять не нужно? | Оба вопроса относятся к свойству решения; сам продукт не исключается |
| I07 | Солнечная станция не даст резерв? | Вопрос о резерве сохраняет тему станции и её ограничения |
| I08 | Приборы можно собрать в единый кабинет? | Платформа находится по смыслу без обязательных слов «учёт электроэнергии» |
| I09 | Нужен единый кабинет для кадров | По одной фразе «единый кабинет» не назначается электроучёт |
| I10 | Нужны и солнечные панели, и учёт по арендаторам | Сохраняются оба продукта и отдельные условия каждого |
| I11 | Солнечные станции и оптовый рынок не нужны, нужен учёт | Общий отказ от перечисления относится к обоим отказанным продуктам |

## История и поправки

В строках ниже реплики клиента идут слева направо. Предыдущие ответы ассистента
нужно сохранять при реальном прогоне, отдельно от фиксированного тестового диалога.

| ID | Последовательность | Что проверяем |
|---|---|---|
| H01 | Нужны панели → панели больше не рассматриваем, нужен учёт → что понадобится? | Последняя пользовательская тема важнее старой |
| H02 | Клиент отказался от панелей → ассистент ошибочно продолжил про солнечную станцию → клиент спрашивает первый шаг | Ошибка ассистента не превращается в подтверждённый факт клиента |
| H03 | Нужна солнечная станция → пока обсудим учёт → вернёмся к первому варианту | Явный возврат восстанавливает первую тему |
| H04 | Мощность 600 кВт → исправляю: 900 кВт → подготовь резюме | В текущем выводе и простом черновике используется 900 кВт |
| H05 | Потребление 600 тысяч кВт·ч в месяц → исправляю: 900 тысяч → резюме | Потребление не смешивается с мощностью; сохраняется период |
| H06 | Объект — склад → исправляю: завод → резюме | Тип объекта обновляется, старый не выдаётся за актуальный |
| H07 | Ручной сбор показаний → поправка: автоматический сбор → резюме | Обновляется схема учёта |
| H08 | Два разных склада с разной мощностью → поправка по второму | Факты разных объектов не сводятся к одному; неоднозначность явно разбирается |
| H09 | Ассистент спрашивает ценовую категорию → кажется, четвёртая | Короткий ответ связывается с темой вопроса, без заимствования иных утверждений ассистента |
| H10 | Телефон пока не передам → вопрос по продукту | Консультация продолжается без выдуманного контакта и заявки |

## Полезность и источники

| ID | Вопрос или ситуация | Что проверяем |
|---|---|---|
| Q01 | Поддерживаются два тарифа? | Прямой ответ о нужной функции; без ненужного сбора параметров всего парка |
| Q02 | Какие данные нужны для начала? | Конкретный продуктовый список; известные данные не запрашиваются повторно |
| Q03 | Для начала уточните вашу присоединённую мощность + отдельный вопрос о той же мощности | Один запрос параметра, без дублирования |
| Q04 | Суточные показания за два года. Данных хватит? | Проверяются все обязательные условия; разбивка день/ночь не предполагается автоматически |
| Q05 | Техник уже обходит приборы и присылает фото | Не предлагается заново выяснить уже описанный способ сбора |
| Q06 | Бесплатный расчёт означает бесплатные обследование и монтаж? | Бесплатность не переносится на другие работы; порядок оплаты не выдумывается |
| Q07 | Подходит солнечная станция при вечернем потреблении? | Профиль нагрузки отличается от мощности станции; экономия и резерв разделены |
| Q08 | Подтверждены ли показания после проверки серийного номера? | Проверка номера не подменяет условие коммерческого использования показаний |
| Q09 | Можно ли распознать год выпуска? | Год выпуска не превращается в срок поверки; не добавляются лишние условия другого вопроса |
| Q10 | Известна только часть ответа | Полезная подтверждённая часть сохраняется, неизвестное обозначено точно |
| Q11 | Итоговая стоимость? / Подготовь резюме для заявки | Стоимость не считается просьбой создать черновик; резюме содержит слова клиента |
| Q12 | Число или обещание в ответе ссылается на документ | Проверяется смысл утверждения, единица и применимость, а не только существование ID цитаты |

## Техника, изоляция и устойчивость

| ID | Проверка | Ожидаемое поведение |
|---|---|---|
| T01 | Один запрос через API и CSV | Одинаковый CoreRequest, текущая реплика ровно один раз; формулировки ответов могут различаться |
| T02 | Повтор HTTP-запроса с тем же идентификатором | Используется сохранённый результат, модель повторно не вызывается |
| T03 | Два аккаунта и два диалога | Истории изолированы; ядро не хранит чужую историю между запросами |
| T04 | Резюме без явного согласия | Заявка автоматически не создаётся |
| T05 | 401/403, 429, 5xx и таймауты | Ограниченные повторы и общий дедлайн; технический сбой отличается от нехватки знаний |
| T06 | Неверный JSON, несуществующая цитата и обрезанный ответ | Контролируемая ошибка/ограниченная коррекция; выдуманный источник не принимается |
| T07 | Отказ реранкера или дополнительной проверки | Ограниченное по времени поведение, понятное предупреждение, сохранение готового валидного ответа при сбое проверки |
| T08 | Переполнение контекста | Ошибка длины не отключает JSON-настройки следующих запросов |
| T09 | CSV с ведущими нулями в ID | Все ID сохраняются ровно один раз, без перенумерации |
| T10 | Измерение скорости | Поиск, очередь, генерация, проверка и общее время; p50/p95 на одинаковых условиях |

## Где находятся наборы и результаты

- Автотесты — каталог `tests/`; у коллеги три новые файлы называются
  `tests/core/test_role3_*.py`, у Данька — `test_intent_regressions.py` и
  `test_dialogue_quality.py`. Тесты с моками не заменяют реальные ответы модели.
- Закрытые 18 demo, прежние 30 сценариев и критические сценарии роли 3 находятся
  локально в `knowledge-base-work/data/`; они не публикуются в Git.
- Новые 60–100 независимых сценариев и отдельный закрытый финал — задача
  [коллеги три](TASK_3_QA.md), критерии сверяет [Аня](TASK_5_ANYA.md).
  Этот открытый список их не заменяет.
- Правила личных файлов и отчётов — [FILE_OWNERSHIP.md](FILE_OWNERSHIP.md).

Результат фиксировать как: ID → коммит → фактический ответ → источники → ошибка
или выполнение критерия → время → кто проверил. Локальное прохождение не переводить
в обещание конкретного балла сайта. Упаковка ZIP сейчас исключена из работы.
