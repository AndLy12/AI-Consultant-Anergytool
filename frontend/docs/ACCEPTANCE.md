# Сценарии пользовательской приёмки (роль №4)

Проверки интерфейса и пользовательского пути. Содержательное качество ответов
(правильность фактов, уместность уточнений, ссылки на документы) проверяет
роль №3 вместе с ролью №2 — здесь отмечено, какие сценарии от этого зависят.

Условия прогона: backend в режиме `CORE_MODE=stub` или с подключённым ядром,
dev-сервер `npm run dev`, только вымышленные данные.

Обозначения статуса:

- **авто** — закрыт автотестом в `frontend/tests`, прогон проходит;
- **вручную** — проверяется кликами, автотеста нет;
- **ждёт ядра** — поведение зависит от ядра роли №2, на заглушке не проверяется.

## Автоматический прогон

```bash
cd frontend
npm run test:ui       # основной путь, аварийные сценарии, изоляция
npm run test:staff    # экран сотрудника (нужна выданная роль staff)
```

Скриншоты шагов сохраняются в `frontend/tests/shots` и в репозиторий не попадают.

## Форма дефекта

Для найденных дефектов заводим запись в такой форме:

```text
ID:            UI-001
Версия/коммит: <короткий хеш>
Сценарий:      U-13 Заявка целиком
Шаги:          1) … 2) … 3) …
Ожидалось:     …
Фактически:    …
Скриншот:      tests/shots/… (без секретов и реальных данных)
Важность:      блокирующий / высокий / средний / низкий
Ответственный: №4 интерфейс / №1 backend / №2 ядро
Статус:        открыт / исправлен / проверен
```
