# Проверки интерфейса

Прогоны в настоящем браузере через Playwright. Сценарии и их статус описаны
в `../docs/ACCEPTANCE.md`.

## Подготовка

1. Запустить backend (из корня репозитория): `docker compose up --build --wait`.
2. Запустить интерфейс: `npm run dev` в каталоге `frontend`.
3. Браузер: используется скачанный Playwright chromium, а если его нет —
   системный Edge или Chrome. Чтобы не зависеть от системного браузера:

   ```bash
   npx playwright install chromium
   ```

## Запуск

```bash
npm run test:ui      # основной путь, проверка полей, аварийные сценарии, изоляция
npm run test:staff   # экран сотрудника
```

Адрес интерфейса можно переопределить переменной `UI_BASE_URL`.

Для `test:staff` нужен аккаунт `reviewer@example.test` с паролем `TestPass12345`
и выданной ролью:

```bash
docker compose exec backend python -m backend.manage grant-staff --email reviewer@example.test
```

## Что внутри

| Файл | Что проверяет |
|---|---|
| `main-path.mjs` | путь от регистрации до созданной заявки, история, перезагрузка, узкий экран |
| `validation.mjs` | подсказки по полям карточки, ответы 422 и 409 по-русски (дефект UI-001) |
| `failures.mjs` | сбой ядра 503, обрыв сети, правила повтора request_id, двойной клик |
| `isolation.mjs` | два пользователя не пересекаются, правка карточки сбрасывает согласие, одна заявка |
| `staff.mjs` | раздел проверки для сотрудника |
| `lib/harness.mjs` | выбор браузера, вывод шагов, снимки экрана |

Прогоны создают новые аккаунты с адресами вида `main.path.<время>@example.test`,
поэтому не мешают друг другу и не требуют очистки базы. Все данные вымышленные.

Скриншоты шагов складываются в `tests/shots` и в репозиторий не попадают.
