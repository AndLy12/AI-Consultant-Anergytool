# Формат закрытой разметки

Заполненные таблицы размещаются в `../data/review/`, а не в этой папке.
Здесь только заголовки CSV и вымышленный пример JSONL.

`product_facts.csv`: ID, тема, утверждение, условия, ограничения, ID документа
подготовки, относительный путь источника, начальная/конечная строки,
точная цитата и неопределённость. Нумерация строк с единицы, конец включительно.
Для каждой существенной оговорки нужно проверяемое основание.

`cases.jsonl`: одна JSON-запись на сценарий. Обязательны `case_id`, `category`,
`conversation` (реплики только user/assistant), `expected_action`,
`expected_fact_ids`, `forbidden_claims`, `comment`. Последняя реплика — user.
Действия: answered, clarification_needed, insufficient_data, out_of_scope.
У сценария answered должны быть основания. Для отсутствующих сведений
фиксируется граница проверки, а не выдуманный продуктовый факт.

Необязательный `context_fixture` описывает вымышленную строку для отдельного
ручного теста в копии найденного контекста. Скрипт её не вставляет и не
исполняет; такой сценарий исключается из автоматической метрики поиска.

Пример `cases.example.jsonl` не является готовым набором: его учебный факт
нужно определить в отдельном вымышленном документе. Закрытые факты Energytool
и вопросы из реальных материалов в публичные примеры не копируются.

`issues.csv`: структурные ошибки, пробелы, расхождения и внешние предпосылки.
Каждое замечание содержит место, действие и статус. Отсутствие текста в
контексте поиска не означает, что текст отсутствует в самой базе.
